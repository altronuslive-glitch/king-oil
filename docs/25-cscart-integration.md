На установке работают **четыре активные витрины** на одной базе и **общей теме `responsive`**:

| ID | Витрина | Домен | Комментарий |
|---|---|---|---|

## Как сейчас сделан дизайн на стенде

Своей темы **нет**. Поверх стоковой `responsive` наложен CSS-оверлей через штатный аддон
**`my_changes`** (включён, приоритет `4294967294` — грузится последним и перебивает всё).

Путь: `design/themes/responsive/templates/addons/my_changes/`

| Файл | Размер | Назначение |
|---|---|---|
| `hooks/index/head_scripts.post.tpl` | **71 КБ / 924 строки** | весь CSS-оверлей |
| `overrides/views/index/index.tpl` | 17,8 КБ | главная переопределена целиком |
| `hooks/index/content.pre.tpl` | 13 КБ | разметка секций главной |
| `blocks/banners/ko_hero.tpl` | 3,9 КБ | блок героя |

Итого ~106 КБ кастома. Тема продублирована в `var/themes_repository/responsive/...`.

### Что автор сделал правильно (переиспользуем)

- **Скоуп по хосту:** `{if $config.current_host == "kingoil.itb-dev.ru"}` — осознанная защита
  соседних витрин от протечки стилей.
- **Выбор хука:** `index:head_scripts`, а не `index:styles`. Причина задокументирована в шапке
  файла: блок `{styles}` компилирует содержимое в `standalone.css` и **проглатывает сырой
  `<style>`**; `head_scripts` печатает RAW HTML в конце `<head>`, уже после `<link standalone>`,
  поэтому оверлей корректно перебивает бандл.
- **Перечень классов темы**, которые пришлось перебивать (53 штуки: `ty-btn`, `ty-footer`,
  `ty-cart-*`, `ty-checkout*`, `ty-account*`, `ty-breadcrumbs` и др.) — готовая шпаргалка
  для новой темы.

Файл помечен автором как «**Фаза 0**», то есть заведомо промежуточный слой.

### Что в текущем решении плохо

- **Нет версионирования.** Git отсутствует, вместо него **11 ручных бэкапов**
  `head_scripts.post.tpl.bak_20260901_182820` и т. п. Правки шли 18 августа — 1 сентября.
- **Источник потерян.** В шапке файла указан «версионируемый источник»
  `custom/my_changes/head_scripts.post.tpl` — **на сервере такой папки нет**.
- **71 КБ CSS инлайном** в каждую страницу, не кэшируется браузером.
- **Токенов недостаточно для пиксель-перфекта.** На стенде ~19 токенов (только отступы и
  цвета), у нас в [tokens.css](../src/css/tokens.css) — **82**, с полной типографической
  шкалой (`--ko-h1-size`…`--ko-h6-lh`, caption, large, контролы, контейнер, сетка).
  Требование «расхождение 0 px» из `CLAUDE.md` оверлеем недостижимо.

## Принятое решение

**Отдельная тема CS-Cart только для витрины «Омск».**

Клонировать `responsive` → своя тема → назначить на `company_id = 1`. Тогда:

- три чужих магазина физически не затрагиваются;
- хостовые `{if}`-костыли не нужны;
- CSS едет нормальными файлами темы, а не инлайном;
- полный набор наших 82 токенов, пиксель-перфект достижим.

Текущий оверлей после переезда с нашей витрины **снимается** — он станет не нужен.
До этого момента остаётся как справочник.

### Почему не другие пути

| Путь | Почему отклонён |
|---|---|
| Доводка оверлея («Фаза 1») | Быстрее (3–6 дней), но пиксель-перфект недостижим, и мы продолжаем воевать со стоковой темой через `!important` |
| Статика + REST API | Даёт витрину с живыми товарами, но корзина, оформление и ЛК настоящими не станут |
| Разовый экспорт в статику | Годится только как демо: данные замороженные, магазин не работает |

## Что остаётся сделать

1. **Получить доступ в админку** — блокер, см. ниже.
2. **Клонировать тему** `responsive` → своя, назначить только `company_id = 1`.
3. **Перенести фундамент:** 82 токена, локальные `.woff2` (вместо Google Fonts, которые
   тянет текущий оверлей), SVG-спрайт, `base.css` / `components.css` — файлами темы.
4. **Переписать страницы в Smarty-шаблоны:**
   - шапка и раздел «Каталог» — на живое дерево 258 категорий;
   - листинг — на штатный товарный список с фильтрами (учесть Searchanise);
   - карточка товара — характеристики через features, чипсы объёма через варианты;
   - корзина / оформление / ЛК — перестилизовать штатные, не переписывать логику;
   - статические страницы — в CMS-страницы.
5. **Собрать раскладки и блоки** в Layout-редакторе админки.
6. **Прогон адаптива** по 1440 / 1024 / 768 / 480 и приёмка.

**Оценка:** 8–15 рабочих дней активной работы.

## Как повторить разведку

`sshpass` и `plink` на рабочей машине отсутствуют, интерактивный ввод пароля недоступен.
Использовался Python + `paramiko` (версия 5.0.0, уже установлен). Скрипты — во временной
папке, при необходимости пересоздаются. Схема:

```python
import paramiko
c = paramiko.SSHClient()
c.set_missing_host_key_policy(paramiko.AutoAddPolicy())
c.connect('79.133.175.75', username='...', password='...')  # доступы в ACCESS.md
i, o, e = c.exec_command('...')
```

Запросы к базе — через `MYSQL_PWD=... mysql --default-character-set=utf8 -t -e '<SQL>'`.
Флаг `--default-character-set=utf8` обязателен, иначе кириллица приходит вопросительными
знаками. FTP тоже работает (порт 21, встроенный `ftplib`), но SSH удобнее.

Просмотр витрины без авторизации отдаёт 401 — нужен Basic-auth (`ACCESS.md`):

```bash
curl -u ЛОГИН:ПАРОЛЬ https://kingoil.itb-dev.ru/
```
