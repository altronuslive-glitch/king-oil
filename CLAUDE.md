# King-Oil — правила работы над вёрсткой

## Главное правило: пиксель-перфект, без исключений

Вёрстка делается **строго по макету Figma**. Размеры, отступы, кегли, цвета и толщины
берутся из макета, а не подбираются на глаз и не «примерно как рядом».

Файл макета: `fUUdaKDxudos0ygbHbKCNF`, страница «▶ Design» (`22997:107243`).
Артборд десктопа — 1900, контейнер — 1420, боковые поля — 240.

### Как работать

1. **Перед любой правкой размеров** — снять данные из Figma через MCP:
   - `get_metadata` по узлу — координаты и габариты фреймов (из них выводятся паддинги,
     зазоры и высоты блоков);
   - `get_variable_defs` по узлу — цвета, кегли, толщины, интерлиньяж;
   - `get_screenshot` — только чтобы свериться визуально, размеры с картинки не снимать.
2. **После правки** — замерить в браузере и сравнить с макетом числом:
   `getBoundingClientRect()` для габаритов, `getComputedStyle()` для типографики.
   Расхождение допускается **0 px**.
3. Значения писать токенами (`--ko-space-*`, `--ko-h6-size` и т. д.), а не «магическими»
   числами. Если в токенах нужного значения нет — добавить токен, а не хардкодить.
4. **Рамки не должны менять габарит блока.** Если по макету блок 128 px и под ним линия —
   линия рисуется псевдоэлементом или `box-shadow`, иначе `border` добавит лишний пиксель
   (пример: `.contacts__list > li` в `src/css/pages.css`).
5. Любое **осознанное отклонение** от макета (боевой контент вместо рыбы, исправленная
   опечатка дизайнера, добавленный элемент) фиксируется:
   - комментарием в коде рядом с местом;
   - строкой в соответствующем файле `docs/` с датой и причиной.
   Молча отходить от макета нельзя.
6. Если узла в макете нет (страница собрана нами) — за основу берутся уже выверенные
   компоненты и ритм из `docs/01-tokens.md`, а решение записывается в `docs/`.

### Чек-лист перед словами «готово»

- [ ] Числа сняты из Figma, а не на глаз.
- [ ] Замер в браузере совпадает с макетом.
- [ ] Использованы токены.
- [ ] Отклонения задокументированы.

## Структура проекта

- `src/` — готовая статика, её и открывает браузер.
- `partials/` — общие блоки (шапка, футер, спрайт, модалки). После правки:
  `python build-pages.py` — разложит блоки по страницам.
- `build-sprite.py` — пересборка SVG-спрайта (`partials/sprite.html`).
- `docs/` — разбор макета по страницам и компонентам, там же журнал решений.
- `dev-server.py` — локальный сервер без кэша (`python dev-server.py`).
